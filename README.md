## Основные возможности

- Регистрация и аутентификация пользователей (JWT).
- CRUD для курсов и уроков.
- Разграничение прав доступа:
  - **Обычные авторизованные пользователи** — получают список своих курсов/уроков и могут изменять свои объекты.
  - **Модераторы** (группа `moderators`) — просматривают и редактируют **любые** курсы/уроки, но не могут создавать и удалять.
- Анонимным посетителям доступны чтение курсов и уроков, список и профили пользователей, просмотр платежей.
- Автоматическая привязка владельца (`owner`) при создании объектов.
- Фильтрация и сортировка платежей.
- Валидация ссылок на видео: разрешены только YouTube-ссылки.
- Подписки пользователей на курсы.
- Пагинация списков курсов и уроков.
- Автоматические тесты CRUD, прав доступа, подписок и пагинации.
- Кастомная модель пользователя (email как логин).
- Автоматическая документация OpenAPI и интерфейс Swagger UI через drf-spectacular.
- Ручное описание тела запроса подписки и ответов 200, 401 и 404.
- Создание тестовой оплаты через Stripe Checkout: товар, цена и платёжная сессия.
- Сохранение идентификаторов Stripe и ссылки на оплату в модели платежа.
- Проверка положительной суммы платежа и обработка ошибок Stripe.

## Установка и запуск

### 1. Клонирование репозитория
```bash
git clone --branch develop https://github.com/terpi228/lms-api-django.git
cd lms-api-django
```

### 2. Создание и активация виртуального окружения
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Для Linux/macOS активация окружения: `source .venv/bin/activate`.

### 3. Установка зависимостей
```bash
python -m pip install -r requirements.txt
```

### 4. Настройка переменных окружения
Создай файл `.env` в корне проекта со следующим содержимым (пример):
```env
SECRET_KEY=ваш-секретный-ключ
DEBUG=True
USE_POSTGRES=True
POSTGRES_DB=skypro_lms
POSTGRES_USER=postgres
POSTGRES_PASSWORD=ваш_пароль
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
STRIPE_SECRET_CODE=sk_test_replace_me
```

Если не хочешь использовать PostgreSQL, установи `USE_POSTGRES=False` — будет использоваться SQLite.

За основу можно взять `.env.example`. Для тестовой оплаты замени `sk_test_replace_me` своим секретным ключом из тестовой среды Stripe (sandbox). Настройки читаются из `.env` через `python-dotenv`; файл с действующими ключами не включается в Git.

### 5. Применение миграций
```bash
python manage.py migrate
```

### 6. Создание суперпользователя
```bash
python manage.py createsuperuser
```

### 7. Загрузка тестовых данных (опционально)
```bash
python load_data.py
```

### 8. Запуск сервера
```bash
python manage.py runserver
```

После запуска API будет доступно по адресу: `http://localhost:8000/api/`

Swagger UI: [http://127.0.0.1:8000/api/docs/](http://127.0.0.1:8000/api/docs/).

## Документация API и Swagger

- `/api/schema/` — схема OpenAPI для инструментов и клиентов API.
- `/api/docs/` — Swagger UI с описанием запросов и возможностью отправить их через браузер.

После запуска сервера открой Swagger и раскрой нужную операцию. Кнопка **Try it out** позволяет ввести параметры или тело запроса, **Execute** отправляет запрос серверу. Операции POST, PUT, PATCH и DELETE могут изменять данные.

Для защищённых операций:

1. Получи пару токенов через `POST /api/login/`, передав `email` и `password`.
2. Скопируй значение `access` из ответа.
3. Нажми **Authorize** в Swagger, вставь access-токен в поле `jwtAuth` без префикса `Bearer` и подтверди авторизацию.

При ручном обращении к API передавай заголовок `Authorization: Bearer <access_token>`.

Проверка генерации и корректности схемы, включая предупреждения:

```bash
python manage.py spectacular --validate --fail-on-warn
```

Команда выводит схему в терминал. Чтобы сохранить её в файл:

```bash
python manage.py spectacular --validate --fail-on-warn --file schema.yml
```

Для полей `lessons_count` и `is_subscribed` указаны возвращаемые типы `int` и `bool`. Запрос подписки и его ответы описаны вручную через `@extend_schema`. Эти описания не добавляют проверку входящих данных в обработчик.

## API Эндпоинты

Все эндпоинты возвращают JSON. Для защищённых эндпоинтов требуется передавать токен в заголовке:

```
Authorization: Bearer <access_token>
```

### Пользователи

| Метод | URL | Описание | Доступ |
|-------|-----|----------|--------|
| POST | `/api/users/` | Регистрация нового пользователя | Все |
| GET | `/api/users/` | Список пользователей | Все |
| GET | `/api/users/{id}/` | Профиль пользователя | Все |
| PUT/PATCH | `/api/users/{id}/` | Обновление профиля | Авторизованные |
| DELETE | `/api/users/{id}/` | Удаление пользователя | Авторизованные |

**Пример регистрации:**
```text
POST /api/users/
{
    "email": "user@example.com",
    "username": "user123",
    "password": "securepass",
    "first_name": "Иван",
    "last_name": "Иванов"
}
```

### Курсы

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/courses/` | Список курсов: анонимным посетителям и модераторам — все, остальным авторизованным пользователям — свои |
| POST | `/api/courses/` | Создание курса (только не модератор) |
| GET | `/api/courses/{id}/` | Детали курса с вложенными уроками |
| PUT/PATCH | `/api/courses/{id}/` | Обновление (модератор или владелец) |
| DELETE | `/api/courses/{id}/` | Удаление (только владелец и не модератор) |

### Уроки

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/lessons/` | Список уроков: анонимным посетителям и модераторам — все, остальным авторизованным пользователям — свои |
| POST | `/api/lessons/` | Создание урока (только не модератор) |
| GET | `/api/lessons/{id}/` | Детали урока |
| PUT/PATCH | `/api/lessons/{id}/` | Обновление (модератор или владелец) |
| DELETE | `/api/lessons/{id}/` | Удаление (только владелец и не модератор) |

### Подписки

| Метод | URL | Описание | Доступ |
|-------|-----|----------|--------|
| POST | `/api/subscription/` | Добавить или удалить подписку на курс | Авторизованные |

Повторный POST для той же пары пользователя и курса удаляет существующую подписку.
В ответах курса поле `is_subscribed` показывает состояние подписки текущего пользователя.

Тело запроса:

```json
{"course": 1}
```

Ответ 200:

```json
{"message": "Подписка добавлена"}
```

При повторном запросе возвращается `{"message": "Подписка удалена"}`. В документации также описаны ответы 401 (нет действительной авторизации) и 404 (курс не найден); их тело содержит строковое поле `detail`.

### Пагинация

Списки курсов и уроков возвращаются страницами по 10 объектов:

```text
GET /api/courses/?page=1
GET /api/courses/?page=1&page_size=5
```

Параметр `page_size` изменяет размер страницы, максимальное значение — 100.

В ответе `count` — общее число доступных объектов, `results` — объекты текущей страницы, `next` и `previous` — ссылки на соседние страницы или `null`, если соответствующей страницы нет.

### Платежи

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/payments/` | Список платежей (с фильтрацией и сортировкой) |
| POST | `/api/payments/` | Создание платежа |

**Фильтры:** `paid_course`, `paid_lesson`, `payment_method`  
**Сортировка:** `ordering=payment_date` (по умолчанию — по убыванию даты)

Чтение платежей доступно всем; создание, изменение и удаление — авторизованным пользователям.

Способы оплаты: `cash` — наличные, `transfer` — перевод, `stripe` — Stripe Checkout. Сумма `amount` должна быть больше нуля. Нужно указать либо `paid_course`, либо `paid_lesson`, но не оба одновременно.

При создании платежа со способом `stripe` сервер:

1. Создаёт товар с названием и описанием выбранного курса или урока.
2. Создаёт разовую цену в USD. Сумма из `amount` переводится в центы: `10.00` → `1000`.
3. Создаёт Checkout Session для одной единицы товара.
4. Сохраняет платёж, текущего пользователя, идентификаторы Stripe и ссылку на оплату.
5. Возвращает запись платежа с кодом 201.

Поля `user`, `payment_date`, `stripe_product_id`, `stripe_price_id`, `stripe_session_id` и `payment_url` доступны клиенту только для чтения. Для `cash` и `transfer` запросы к Stripe не выполняются.

Ошибки: 400 — некорректные входные данные, 401 — отсутствует действительная авторизация, 502 — ошибка при обращении к Stripe. При ошибке Stripe новая запись платежа не сохраняется. Уже созданные на стороне Stripe товар или цена при этом автоматически не удаляются.

Каждый новый POST создаёт отдельный платёж и новые объекты Stripe. Повторная отправка не переиспользует ранее созданную сессию. Изменение существующей записи через PUT/PATCH не пересоздаёт сессию Stripe.

## Тестирование оплаты Stripe

1. Настрой `STRIPE_SECRET_CODE` в `.env`, установи зависимости и примени миграции командой `python manage.py migrate`.
2. Запусти сервер, получи access-токен через `/api/login/` и авторизуйся в Swagger.
3. Выбери существующий курс. В примере ниже используется `paid_course: 7` из локальной тестовой базы; после нового клонирования создай курс и подставь его фактический ID. Данные PostgreSQL не хранятся в Git-репозитории.
4. Выполни `POST /api/payments/` с телом:

```json
{
    "paid_course": 7,
    "amount": "10.00",
    "payment_method": "stripe"
}
```

5. В ответе 201 проверь заполнение `stripe_product_id`, `stripe_price_id`, `stripe_session_id` и `payment_url`. Открой URL из `payment_url`.
6. Для успешной тестовой оплаты используй карту `4242 4242 4242 4242`, будущую дату (например, `12/34`), CVC `123` и тестовые имя и email. В sandbox реальные деньги не списываются. Актуальные сценарии и номера карт приведены в [документации Stripe](https://docs.stripe.com/testing).
7. После оплаты Stripe перенаправит браузер на `/api/docs/`. В текущем коде отмена оплаты возвращает туда же, поэтому сам переход в Swagger не подтверждает успешную оплату. Результат можно посмотреть в тестовом кабинете Stripe.

Идентификаторы и ссылка сохраняются в базе при создании сессии, до оплаты. Автоматическое обновление статуса платежа, webhooks и выдача доступа к курсу после оплаты не реализованы. Создание сессии также не переключает подписку на курс.

Функции обращения к Stripe находятся в `users/services.py`; их вызывает `PaymentViewSet.perform_create`. Адреса возврата пока заданы в сервисе как `http://127.0.0.1:8000/api/docs/` и рассчитаны на локальный запуск. Текущий учебный API принимает сумму от клиента; фиксированная серверная цена курса отдельно не хранится.

## Права доступа

- **IsAuthenticated** — требуется авторизация.
- **IsModer** — пользователь состоит в группе `moderators`.
- **IsNotModer** — пользователь не состоит в группе `moderators`.
- **IsOwner** — пользователь является владельцем объекта (поле `owner`).

Комбинации:
- `[IsAuthenticated(), IsNotModer()]` — только авторизованные, кроме модераторов.
- `[IsAuthenticated(), (IsModer | IsOwner)()]` — авторизованные и (модератор ИЛИ владелец).
- `[IsAuthenticated(), IsOwner(), IsNotModer()]` — авторизованные, владелец, и не модератор.

## Тестирование в Postman

1. Импортируй коллекцию `LMS_API_Postman_Collection.json` (лежит в корне проекта).
2. Создай пользователя через `POST /api/users/`.
3. Получи токены через `POST /api/login/`.
4. Для защищённых запросов добавь заголовок:
   ```
   Authorization: Bearer <access_token>
   ```
5. Проверь сценарии:
   - Обычный пользователь создаёт курс — в ответе должен быть `owner` с его ID.
   - Обычный пользователь пытается отредактировать чужой курс — получает 404, поскольку чужой объект исключён из его queryset.
   - Модератор (добавленный в группу через админку) может редактировать любой курс, но не может создать или удалить.
   - Авторизованный пользователь добавляет и удаляет подписку через `POST /api/subscription/`.
   - В ответах курса проверяется поле `is_subscribed`.
   - `GET /api/courses/?page=1&page_size=5` возвращает не более 5 объектов.
